# 017 - Pre-Wizzy hostile-surface audit

PW-010 requires a census, not a reassurance. This document classifies the
current input surfaces before Wizzy integration. It does not change a register
state or upgrade an old test result. The phase-close ADR must bind the final
version of this census and every cited check to one clean commit.

An input is hostile here when it comes from ring 3, firmware, a bootloader, a
device, persistent media, an external process, the repository filesystem, or
an arbitrary safe caller of `wost`. Each row is grouped at the first validator
or authority boundary. The fail-closed rule must dominate every subsequent
length calculation, index, shift, pointer formation, hardware write and
fallible callee. A listed check means an oracle exists; it does not mean the
current phase-close run passed. `OPEN` and `TRIGGER` refer to the finite
[pre-Wizzy register](016-pre-wizzy-foundation.md).

Within a proof cell, an explicit `` `OPEN`: `` segment ends at the next
semicolon or the cell boundary. Every `PW-*` row in that segment must currently
be `REQUIRED`, `READY`, `VERIFY` or `DECIDE`; closed proof and stopped triggers
stay outside it.

Static banners/themes, constant-only vector tables, module routing and
self-test-only observation seams have no independent input surface. They are
covered at the first consumer that accepts bytes, state or authority rather
than receiving duplicate rows here.

In the tables, "machine checks" means the checked registry in
[`kernel/src/selftest.rs`](../kernel/src/selftest.rs); "source contracts" means
[`xtask/src/contracts.rs`](../xtask/src/contracts.rs); "API audit" means
[`xtask/src/api.rs`](../xtask/src/api.rs); and "TLA models" means
[`Ring.tla`](../models/Ring.tla) and [`RingMemory.tla`](../models/RingMemory.tla)
through the bounded [`model` observer](../xtask/src/model.rs).

## Boot handoff and privileged adapters

The bootloader's promise that a reported mapping is actually accessible is a
platform trust root; Rust cannot probe an arbitrary address without risking a
fault. The kernel nevertheless validates presence, length, arithmetic,
classification and all later content before deriving narrower authority.
Device state is treated differently: where hardware exposes readable state and
later safety depends on a write, the adapter must read it back or retain
ownership on uncertainty. Architecturally defined x2APIC MSR-write semantics
remain a processor trust assumption where no independent readback exists.

## Host tooling and evidence

Host tooling handles locally hostile paths and bytes even though a user able to
race the repository already has the contributor's authority. A checked path is
opened without following its final component, and the opened handle must
describe one real file (D-344), so a link swapped in after the check is never
read. Because the standard library offers no directory-relative open on
Windows, replacing the whole parent directory between validation and use
remains an explicit limit (limit 3); the tooling must not claim that path
preflight eliminates it.

## Threat model and trust boundaries

The tables above treat each input in the opening paragraph as hostile at its
first validator. This section names what the kernel and its tooling still
trust, what each checks before relying on that trust, and which limit or
register row owns the rest; it records no qualification result.

**Operator, `PATH` and account.** `cargo xtask` runs with the operator's
account, so a process running as that account can change the checkout, `PATH`,
the tools `PATH` names and `target/`. The tooling cannot prevent that; it
records which tools answered, so a substitution is visible in the evidence. A
run resolves Git once, refuses an executable whose version does not name Git,
and binds its path, version, length and SHA-256 into every qualification record
and the evidence manifest, measured again before either is committed; checked
paths open without following their final component (D-344, `88d529d`). The
manifest also binds QEMU and both firmware images by digest (D-216), and
`cargo xtask verify-evidence` requires the verifying host to match. QMP runs
over the QEMU child's own standard streams and no boot binds a control listener
(D-346, `2889b75`); the `debug` task's loopback GDB server serves a paused
private machine that no record reads (D-231). A bounded command's Windows job
ends with the command, its timeout or its failure; a hard external kill of
`xtask` leaves the job's processes running, and a non-Windows host stops only
the direct child until `PW-708` (D-347, `c26f083`). The `xtask` grade and the
VMware boots are human trust boundaries (D-330).

**Firmware, hypervisor and ACPI.** Firmware, and on a virtual machine the
hypervisor, is trusted to describe the machine, and the kernel bounds each
description before use. ACPI tables are read only from ACPI-only memory and
need a valid length, checksum and signature before any field is used
(`acpi-tables`, `FirmwareMemory`). The MADT's I/O APIC address is trusted: the
takeover writes the select register there once to read the version, and
refuses a window whose version byte lies outside 0x11 to 0x20 or whose count
exceeds 240 before any mask or redirection write (D-350, `2e27225`,
mutations 1,531 and 1,532). The DMAR is read once at boot and refused when a
structure or device scope is truncated or overruns its container, a reserved
region is inverted, or two units share a register base; the duplicate-unit and
inverted-region checks carry mutations 1,540 and 1,541. A unit's register base
is trusted to name the governing unit and passes device-range admission, which
needs the runtime physical width and excludes every boot-map byte. Up to eight
regions the DMAR reserves for the function are identity-mapped read and write
for the domain's life, and the candidate is refused before takeover when a
page one of them reaches is RAM or firmware storage (D-360, mutations 1,573
through 1,578 and 1,589). A hostile monitor can spoof CPUID,
so the QEMU TCG mapping reason is trusted development configuration and attests
nothing (D-250).

**Bootloader and CPU contracts.** The kernel requests Limine base revision 4
and stops in `kernel_main` if it is not honored
([`limine_glue.rs`](../wost/src/boot/limine_glue.rs)); a missing response stays
a typed error, and replacing Limine waits for `PW-705`. The memory map is
accepted all or nothing (`memory-map`), but whether a reported mapping is
accessible is the bootloader's promise (limit 1). A user process shares kernel
mappings only on an affirmative `RDCL_NO` or the exact QEMU TCG tuple (D-250);
native hardware without `RDCL_NO` needs KPTI first (`PW-706`). Ring 3 also
needs enforced NX and a calibrated clock, while missing SMEP, SMAP or UMIP is a
supported diagnostic fallback (D-201). Where an x2APIC MSR write offers no
readback, the architecture is trusted (limit 2).

**Device DMA.** The kernel admits the storage controller to bus mastering only
behind an Intel VT-d domain that identity-maps the frames a live `DmaSegment`
owns and the function's reserved regions, so while translation is on every
other address faults (D-357, D-358). Queue frames enter the domain before the
controller learns them; a transfer buffer is mapped before its doorbell and
unmapped, with an invalidation, after its completion or a proven stop.
Admission needs a `DmaDomain` for the exact function, minted only while
translation is on and the root and context entries name the kernel's own
tables, and spends it: the proof is neither `Clone` nor `Copy`, so none
outlives a release (D-360, mutations 1,579 and 1,580). Without a usable unit the boot says `storage: no DMA isolation` and
starts no storage, which `cargo xtask degraded-check` requires on a machine
without one (mutation 1,549); D-358 records both self-tests at 270/270 on
QEMU's `intel-iommu` unit and one red for each of
mutations 1,540 through 1,569. The fence holds only while translation is on, so
a device that ignores its bus-master enable bit is unconstrained before
establishment, after release, behind a unit the kernel cannot take over and
under any unit it never takes over (D-358, left owed; limit 2). Still stopped:
device interrupts are not remapped (`PW-710`), AMD units have no backend
(`PW-711`), and a device sees the physical addresses of its buffers (`PW-712`).

**Census limits.** The four limits below are what the census cannot discharge:
mapping and instruction contracts, ignored device writes, a parent directory
replaced between check and open, and processes outside the Windows job.

Four limits stay explicit:

1. The bootloader and CPU must honor their architectural mapped-memory and
   instruction contracts. Parsers can bound reported ranges; they cannot make
   an unmapped physical address safe to dereference.
2. A device can ignore writes. Readable state that gates memory or interrupt
   safety needs readback or retained uncertainty; a successful bus transaction
   alone is not proof. Architecturally specified x2APIC MSR-write behavior is a
   named processor assumption where the interface offers no independent
   readback.
3. A checked path is opened without following its final component (D-344).
   A same-authority process that replaces the whole parent directory between
   the check and the open, with one holding a file of the same name, is not
   stopped, because the standard library offers no directory-relative open on
   Windows.
4. On Windows every bounded command runs in a job object that holds the child
   before it runs and is terminated whenever the command completes, times
   out, overruns its capture limit or cannot be observed (D-347). D-347's
   fixtures saw a parked grandchild release its exclusive file after both a
   normal completion and a timeout, and mutations 1,522 and 1,523 retain both
   reds. A hard external kill of `xtask` itself leaves the job's processes
   running, and a non-Windows host stops only the direct child until `PW-708`
   adds process groups.

The library set is mechanically guarded by `boundary.rs`. The adapter, kernel
and tooling tables remain an adversarial review census: the phase-close ADR
must re-read them against the final source, enumerate every `OPEN` disposition,
link the current mutation/model/machine/external-grader evidence and record any
new defect in the finite register before calling PW-010 complete.
