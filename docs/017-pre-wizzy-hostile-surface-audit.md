# 017 - Pre-Wizzy hostile-surface audit

PW-010 requires a census, not a reassurance. This document classifies the
current input surfaces before Wizzy integration. It does not change a register
state or upgrade an old test result. The phase-close ADR must bind the final
version of this census and every cited check to one clean commit.

An input is hostile here when it comes from ring 3, firmware, a bootloader, a
device, persistent media, an external process, the repository filesystem, or
an arbitrary safe caller of `wost`. Each row is grouped at the first validator
or authority boundary. The fail-closed rule must dominate every subsequent
length calculation, index, shift, pointer formation, hardware write and
fallible callee. A listed check means an oracle exists; it does not mean the
current phase-close run passed. Rows summarize each rule; the cited decision
owns its full statement, and the [mutation registry](../xtask/src/mutate/registry/)
owns each retained mutation and the red it must produce. `OPEN` and `TRIGGER`
refer to the finite [pre-Wizzy register](016-pre-wizzy-foundation.md).

Within a proof cell, an explicit `` `OPEN`: `` segment ends at the next
semicolon or the cell boundary. Every `PW-*` row in that segment must currently
be `REQUIRED`, `READY`, `VERIFY` or `DECIDE`; closed proof and stopped triggers
stay outside it.

Static banners/themes, constant-only vector tables, module routing and
self-test-only observation seams have no independent input surface; they are
covered at the first consumer that accepts bytes, state or authority.

In the tables, "machine checks" means the checked registry in
[`kernel/src/selftest.rs`](../kernel/src/selftest.rs); "source contracts" means
[`xtask/src/contracts.rs`](../xtask/src/contracts.rs); "API audit" means
[`xtask/src/api.rs`](../xtask/src/api.rs); and "TLA models" means
[`Ring.tla`](../models/Ring.tla) and [`RingMemory.tla`](../models/RingMemory.tla)
through the bounded [`model` observer](../xtask/src/model.rs).

## Boot handoff and privileged adapters

The bootloader's promise that a reported mapping is accessible is a platform
trust root, because Rust cannot probe an arbitrary address without risking a
fault; the kernel still validates presence, length, arithmetic, classification
and all later content before deriving narrower authority. Where hardware
exposes readable state and later safety depends on a write, the adapter must
read it back or retain ownership on uncertainty. Architecturally defined x2APIC
MSR-write semantics remain a processor trust assumption where no independent
readback exists.

## Threat model and trust boundaries

The tables treat each input in the opening paragraph as hostile at its first
validator. This section names what the kernel and its tooling still trust and
which limit or register row owns the rest; it records no qualification result.

**Operator, `PATH` and account.** `cargo xtask` runs with the operator's
account, so a process running as that account can change the checkout, `PATH`,
the tools `PATH` names and `target/`. The tooling cannot prevent that; it
records which tools answered, so a substitution is visible in the evidence. A
local qualification record is therefore not an authentication boundary against
another process with concurrent write authority over the checkout and
`target/`, which can replace source, executables and every local record. D-373
removes the supported elevation of an arbitrary caller-selected
result directory into PASS; it does not claim that checksummed local files
authenticate against the operator account that owns them. The release flow
requires an exclusive clean run under that account, while offline transport
uses the recorded hashes to detect later substitution. Git identity and checked
reads follow their row (D-344, `88d529d`). The evidence manifest binds QEMU and
both firmware images by digest, and `cargo xtask verify-evidence` requires the
verifying host to match (D-216). QMP uses the QEMU child's own standard streams
(D-346, `2889b75`), and the `debug` task's loopback GDB server serves a paused
private machine that no record reads (D-231). The Windows job and the processes
outside it are limit 4 (D-347, `c26f083`). VMware boots remain a human trust
boundary. The `xtask` grade owns its complete bounded process tree and uses
only source-controlled adjudications. D-406 gives Deep the same exclusive-run
trust boundary only for a pinned Windows Job-owned live MCP session; imported
output remains diagnostic and has no PASS authority. D-420 adds the
owned-clone, credential-alias and worker-side confidentiality boundary. Under
D-422 the authenticated app-server keeps its provider profile for
configuration, account and API orchestration only, and every exec remains a
mandatory wrapper crossing, the only place the provider invocation is validated
and attenuated. The live credential has exactly one name before its one owned
projection, and both names stay explicitly denied and identity-checked for
model workers. This split remains unqualified until a complete clean frozen
owned run passes; D-425 superseded PW-026 as a release prerequisite, so that
run's record enters only a release with the same source.

**Firmware, hypervisor and ACPI.** Firmware, and on a virtual machine the
hypervisor, is trusted to describe the machine, and the kernel bounds each
description before use. ACPI tables are read only from ACPI-only memory and
need a valid length, checksum and signature before any field is used
(`acpi-tables`, `FirmwareMemory`). The MADT's I/O APIC address is trusted, as
the I/O APIC routing row states (D-350, `2e27225`). A DMAR unit's register base
is trusted to name the governing unit and passes device-range admission; its
authority follows the remapping-unit row (D-389), and candidate lookup refuses
any applicable reserved region (D-388). A hostile monitor can spoof CPUID, so
the QEMU TCG mapping reason is trusted development configuration and attests
nothing (D-250).

**Bootloader and CPU contracts.** The kernel requests Limine base revision 4
and stops in `kernel_main` if it is not honored
([`limine_glue.rs`](../wost/src/boot/limine_glue.rs)). Whether a reported
mapping is accessible is the bootloader's promise (limit 1). A user process
shares kernel mappings only on an affirmative `RDCL_NO` or the exact QEMU TCG
tuple (D-250); native hardware without `RDCL_NO` must instead use D-407's
paired KPTI mode, whose stripped root maps above the shared user subtree only
dedicated page-bounded assembly, hardware-read descriptors, non-secret routing
state and guarded scrubbed entry stacks. v0.2.0 closed `PW-580` and `PW-706` on
`694061f`, where the fresh VMware qualifications read capabilities `0x44` and
selected paired roots (D-449). No absent architectural bit is inferred. Ring 3
also needs enforced NX and a calibrated clock, while missing SMEP, SMAP or UMIP
is a supported diagnostic fallback (D-201). Where an x2APIC MSR write offers no
readback, the architecture is trusted (limit 2).

**Device DMA.** The storage controller gets bus mastering only behind an Intel
VT-d domain that identity-maps the frames a live `DmaSegment` owns and rejects
every firmware-reserved DMA region, so while translation is on every other address faults (D-357, D-358, D-388).
Translation is kernel-owned before PCI discovery, and accepted DMAR and `WZDM`
addresses are trusted platform authority (D-389, Codex Security occurrence
`occ_9a4891f61ef72658a0f921ef`). Admission spends a non-`Clone`, non-`Copy`
`DmaDomain` proof for the exact function, minted only while translation is on
and the root and context entries name the kernel's own tables (D-360), and
borrows the exact unit so its owner cannot be destroyed or reused first
(D-433). Without a usable unit the boot says `storage: no DMA isolation` and
starts no storage, which `cargo xtask degraded-check` requires on a machine
without one. A device that ignores its bus-master enable bit remains
unconstrained before the earliest kernel takeover, behind a unit the kernel
cannot take over and under any unit it never takes over (D-389, separately
owed; limit 2). D-372 owns all PCI interrupt delivery through an empty
interrupt-remapping table and keeps legacy I/O APIC lines masked. Still
stopped: AMD units have no backend (`PW-711`), and a device sees the physical
addresses of its buffers (`PW-712`).

Four limits stay explicit:

1. The bootloader and CPU must honor their architectural mapped-memory and
   instruction contracts. Parsers can bound reported ranges; they cannot make
   an unmapped physical address safe to dereference.
2. A device can ignore writes. Readable state that gates memory or interrupt
   safety needs readback or retained uncertainty; a successful bus transaction
   alone is not proof. Architecturally specified x2APIC MSR-write behavior is a
   named processor assumption where the interface offers no independent
   readback.
3. A checked path is opened without following its final component (D-344).
   A same-authority process that replaces the whole parent directory between
   the check and the open, with one holding a file of the same name, is not
   stopped, because the standard library offers no directory-relative open on
   Windows.
4. On Windows every bounded command runs in a job object that holds the child
   before it runs and is terminated whenever the command completes, times
   out, overruns its capture limit or cannot be observed (D-347). A hard
   external kill of `xtask` itself leaves the job's processes running, and a
   non-Windows host stops only the direct child until `PW-708` adds process
   groups.

The library set is mechanically guarded by `boundary.rs`. The adapter, kernel
and tooling tables remain an adversarial review census: the phase-close ADR
must re-read them against the final source, enumerate every `OPEN` disposition,
link the current mutation/model/machine/external-grader evidence and record any
new defect in the finite register before calling PW-010 complete.
