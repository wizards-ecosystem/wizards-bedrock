# v0.3.0: The source coherence release

v0.3.0 is Bedrock's second diagnostic release. The tag names `dc762a2`, the exact
commit every check below ran against; it never moves. This is an experimental
x86_64 UEFI kernel for study and testing in disposable virtual machines. It is
not a complete operating environment, a stable ABI, production software or a
completed security audit.

## What changed

- **One coherent source.** Every crate was restyled to one set of conventions:
  long functions split into named steps, names in whole words, comments kept to
  the reasons code cannot show, public items narrowed to what other crates use,
  and physical addresses given their own type (`libs/address`).
- **A minimal test suite (D-454).** The suite keeps a boot smoke that scans the
  serial log, syscall and ABI behaviour, isolation and security, a few edge tests
  per hostile-input parser, a regression per fixed bug and a small tooling smoke
  set: 211 machine checks, 52 library tests with one example per crate, and 16
  tooling tests. The hand-written mutation registry, source-text contract tests,
  doc-pinning tests, the API caller audit, the qualification records and the deep
  security scan are gone. `cargo mutants` and fuzzing are on-demand laptop work.
  Docs never fail a build.
- **A cold read of every production file**, with these fixes among others:
  - a first NVMe failing before isolation no longer quarantines the VT-d unit for
    the whole boot;
  - new threads start with MXCSR at its reset value, so SIMD exceptions stay masked;
  - interrupts stay off unless the PCI interrupt isolation proof holds;
  - a rolled back page-table link is invalidated before its frame is freed;
  - shared memory maps non-executable;
  - a fence whose restore cannot be verified never revives bus mastering;
  - the gate refuses a stale `Cargo.lock` and lints every workspace member.
- **A small lint set** that denies `unwrap`, `expect`, unexplained `allow`, debug
  leftovers and casts `From` can do.
- **The roadmap** is rooted in worlds (D-453, `docs/021-roadmap.md`).
- **Reproducible on Linux.** The alternate evidence build no longer inherits the
  original toolchain's loader path. The evidence format is v13.

## What ships

- `wizards-bedrock-v0.3.0-x86_64-uefi.zip`: the reproducible shipped boot image
  `bedrock.img`, the kernel ELF `wizard-kernel`, `LICENSE`, the SPDX SBOM,
  third-party notices and every bundled license, with an inner `SHA256SUMS`.
- `wizards-bedrock-v0.3.0-evidence.zip`: the v13 evidence bundle that
  `cargo xtask verify-evidence` replays offline.
- `wizards-bedrock-v0.3.0-MANIFEST`: the bundle manifest.
- `SHA256SUMS`: digests of the three files above.

The image boots to Bedrock's diagnostic keyboard prompt after bringing up paging,
the EEVDF scheduler, ring 3, VT-d default-deny DMA translation, NVMe and
read-only FAT32. There is no shell or user program.

## Checks, all on `dc762a2`

- `cargo xtask ci` on Linux: formatting, Clippy over the host, shipped, self-test
  and `refuse-pci` graphs, docs, host tests, supply chain, vendored digests,
  release and debug self-tests at 211/211, the shipped boot check and the
  fail-closed degraded boots.
- `cargo xtask evidence` and `cargo xtask verify-evidence`: the shipped kernel and
  image built twice from independent source, Cargo-home and toolchain paths are
  byte-identical (kernel `a1abb6b1...`, image `e9174a90...`), and the bundle
  verifies offline. The bundle shows it is consistent, not who made it.
- VMware Workstation: the self-test machine at 211/211 and the shipped machine
  reaching its prompt with DMA translation on and ring 3 running, both accepted by
  `cargo xtask qualify-vmware`.

## Known open

The [foundation register](../016-pre-wizzy-foundation.md) lists every live row:
PW-006 and PW-010 still need the hostile-surface audit, and TRIGGER rows wait on
their named conditions. A machine with more than twelve requesters behind one
VT-d unit keeps maskable interrupts off. The clean Windows quickstart check is
[issue #2](https://github.com/wizards-ecosystem/wizards-bedrock/issues/2). No
bare-metal hardware is qualified.

## Verify

Download the four assets and check them with `sha256sum -c SHA256SUMS`; the
runtime archive carries its own `SHA256SUMS` for its members. To replay the
evidence, extract the evidence archive into `target/` of a clean checkout of this
tag and run `cargo xtask verify-evidence`, which works offline but requires the
recorded tool identities. Boot `bedrock.img` only in a disposable VM.
