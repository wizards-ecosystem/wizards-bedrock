# D-417 The owned Deep runtime advances only as one remeasured exact tuple

Status: Accepted, 2026-10-17. Implemented with qualification OPEN; amends D-406, D-411 and D-413; advances PW-026.

**Context.** Before D-416's first owned scan could start, the ChatGPT Codex
installation advanced and removed D-406's selected `0.162.0-alpha.17.2`
four-file runtime directory. The qualifier stopped while inspecting that
missing ancestor, before login, effective-configuration reading, the Daybreak
advisory or Deep start. The installed Codex Security 0.1.32 package and its 47
tool descriptors were unchanged, but substituting an ambient `codex` command,
selecting the newest directory or retaining only the version string would
discard the exact executable authority D-406 requires.

**Decision.** The owned tuple advances to the current official CUA Node child
`a5a02988362ca169` (`v24.21.0`, 93,381,936 bytes, SHA-256
`81690694aa9c11d3d4b4503f467182bf63e2859bdc0269eeb61dc89a5819cf50`)
and Codex child `e78bad9887fa50cf`. The Codex entrypoint is
`codex-cli 0.163.0-alpha.10.2`, 341,312,816 bytes with SHA-256
`9ecb9df2ecafcc00542ef0966c6f1737a81397dc9531b0a4b178238e2bf4a46d`.
Its exact adjacent four-file tree is 442,152,128 bytes with folded SHA-256
`5e5c505d977265593a37faee54e5952fc6cbf4ff00c0de05db0f614c9a1e0094`.
The qualifier still names those content-addressed children directly, hashes
every file before use, remeasures the complete tuple after its last use and
refuses missing, added, redirected, ambiguous or changed bytes.

Two fresh empty private homes independently returned the same strict
initialize/config schemas, canonical 3,056-byte originless default projection
with SHA-256
`ca92daadf6d70a31d9f9e9463dfb19916376b40d3da96950e43dafac1bdaa3bf`,
and generated system-skills tree of 71 entries and 314,963 file bytes. The
separate compatibility probe reported folded SHA-256
`1715d9d4d5d41e12e37d33e46d44d970ca64f298846430a20c6af04c8f1caf7c`.
Those observations replaced the old runtime's trusted data; no schema or
tree-shape predicate was widened. D-419 corrects the probe's host-culture path
ordering to the production verifier's ordinal ordering without changing the
observed tree.

The new runtime preserves every fixed safety value but omits an origin for
`notify=[]` when that override equals its empty originless default. The
qualifier retains the explicit override and exact effective-empty check, keeps
`notify` in the allowed-origin set, and exempts only that field from mandatory
origin presence. It now also requires the empty private home's originless
notification value to be inert before constructing overrides, closing the
otherwise unhashed value that D-412 intentionally parses separately.

**Proof.** Both controlled private-home probes exited successfully, emitted no
trailing output and produced identical canonical defaults and independently
measured system-skill summaries; their exact temporary roots were then removed.
The focused Deep
configuration, protocol, runtime, request and verifier suite accepts the new
tuple and origin behavior while retaining every drift refusal. Mutation 2,085
admits an active originless notification command and fails only
`originless_ambient_notifications_are_refused_before_safety_overrides`.

**Qualification boundary.** The source change invalidates every exceptional
record made on `6d2b9ee`. PW-026 remains open until one new clean frozen commit
passes the complete current mutation registry and the real D-406/D-416/D-417/D-419
owned Deep run, whose artifacts are replayed into final evidence.

**Alternatives.** Restoring deleted executables, selecting from `PATH`, or
accepting any installed version was rejected because none binds the process
that receives the credential and launches workers. Requiring a `notify` origin
was rejected because this exact runtime truthfully elides a no-op override;
dropping the override, empty-value check or ambient-default check was rejected
because any one would weaken the side-effect boundary.
